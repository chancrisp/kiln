# Drag Results Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A held result can be dragged out of Kiln into Explorer or another
app. A move takes it out of holding, and a copy leaves it held.

**Architecture:**
- The model (`model.rs`) owns everything testable: the new saved state, the
  row line, which files a drag carries, press-and-release selection, the
  drag distance rule, and settling files that disappeared after a drag.
- A new `win/drag_out.rs` wraps the shell calls: a shell data object,
  preferred effect Move, async mode off, and `SHDoDragDrop`.
- `win/mod.rs` wires the pointer and the drop target to them. After a drag,
  Kiln checks which files are gone instead of trusting the returned effect.

**Tech Stack:** Rust, `windows` 0.62. Win32 Shell and OLE features are
already enabled in `crates/kiln-app/Cargo.toml`.

**Spec:** `docs/superpowers/specs/2026-10-20-drag-out-design.md`

## Global Constraints

- Branch `drag-out`. Never push, and never merge without the owner's yes.
  Commits use the owner's git identity, with no AI attribution or trailers.
- Copy, verbatim:
  - row line: `Saved where you dropped it.` (Tone::Result)
  - footer error: `Couldn't start the drag.`
  - help line: key `Drag out`, text `Save a result where you drop it.`
- Move is preferred and Copy allowed. Async mode is off. A drop onto Kiln
  itself does nothing.
- Results saved by a drag aren't held. Results still there after a drag
  stay held.
- No drag while a panel, dialog or the wheel is open, or without a holding
  folder.
- Gates:
  - `cargo fmt --all -- --check`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo test -p kiln-app`

## Review Focus

1. **An optimised move:** Explorer can move the file itself and report
   `DROPEFFECT_NONE`. Kiln must decide by whether each file still exists,
   never by the returned effect (Task 2).
2. **Press-and-release inside a multi-selection:** it must still collapse
   the selection to that row, as a click does today. Only a drag keeps it
   (Task 1 test `a_press_inside_the_selection_waits_for_release`).
3. **A merge result several rows share:** it's carried once, and one move
   marks every row that holds it (Task 1 test
   `a_shared_result_moved_by_a_drag_saves_every_row`).
4. **A result an export is moving, or one that's gone:** a drag must never
   carry it (Task 1 test `a_drag_carries_held_results_of_the_selection`).
5. **A dragged file that disappears later:** the row must read
   `Saved where you dropped it.`, never the gone sentence (Task 1 test
   `files_gone_after_a_drag_were_moved_not_lost`; Task 2 calls it in
   `check_gone` before the gone check).

### Task 1: The model

**Files:**
- Modify: `crates/kiln-app/src/model.rs` (JobState::Done, Entry::line, Entry::saved, FileList, constants, tests)
- Modify: every match on `saved: Some(folder)` / `saved: None` that the compiler flags (model.rs, ways_in.rs, a11y.rs, win/mod.rs, win/render.rs)

**Interfaces:**
- Produces:
  - `pub enum Saved { Folder(PathBuf), Dropped }` (derive Debug, Clone, PartialEq, Eq). `JobState::Done.saved` becomes `Option<Saved>`. `None` still means held.
  - `Entry::saved(&self) -> Option<(&Path, &[PathBuf])>`: unchanged signature, `Saved::Folder` only. A dropped row has no folder to show or open, so it's `RowState::Plain`, has no link, and double-click does nothing.
  - `pub const DROPPED: &str = "Saved where you dropped it.";`
  - `pub const DRAG_FAILED: &str = "Couldn't start the drag.";`
  - `FileList::dragged_out(&mut self, moved: &[PathBuf])`: the drag twin of `exported`. A row whose held results are all in `moved` becomes `saved: Some(Saved::Dropped)`, with outputs kept. A row with some left keeps holding only those.
  - `FileList::drag_files(&self, skip: impl Fn(&Path) -> bool) -> Vec<PathBuf>`: the held files of the selected rows, once each, in list order, minus those `skip` names (saving or missing).
  - `FileList::press(&mut self, i: usize) -> bool`: a plain press on row `i`. If `i` is in a selection of two or more, it sets focus and anchor to `i`, keeps the selection, and returns `true` ("collapse on release"). Otherwise it does what `click(i)` does and returns `false`.
  - `FileList::settle_drags(&mut self, dragged: &HashSet<PathBuf>, exists: impl Fn(&Path) -> bool) -> bool`: calls `dragged_out` with every held file that's in `dragged` and doesn't exist. Returns whether anything changed.
  - `pub fn past_drag(dx: f32, dy: f32, half_w: f32, half_h: f32) -> bool`: `true` once `|dx| > half_w || |dy| > half_h`.

- [ ] **Step 1: Write the failing tests** in `model.rs` `mod tests`. Use the existing `held_row(name, outputs, saved)` helper, adjusted to the new type.

```rust
#[test]
fn a_dragged_out_row_says_where_it_went() {
    let mut list = list_of(&[held_row("a.png", &["a.jpg"], None)]);
    list.dragged_out(&[PathBuf::from("a.jpg")]);
    let e = &list.entries()[0];
    assert_eq!(e.line(), ("Saved where you dropped it.".to_owned(), Tone::Result));
    assert_eq!(e.held(), None);
    assert_eq!(e.saved(), None);
    assert_eq!(e.link(false), None);
    assert!(!e.is_gone(|_| false));
    assert_eq!(e.row_state(false, |_| false), RowState::Plain);
    assert_eq!(list.held_count(), 0);
}

#[test]
fn a_partly_dragged_row_keeps_the_rest() {
    let mut list = list_of(&[held_row("talk.mp3", &["p 1.mp3", "p 2.mp3", "p 3.mp3"], None)]);
    list.dragged_out(&[PathBuf::from("p 1.mp3")]);
    assert_eq!(list.entries()[0].line().0, "Ready: p 2.mp3 and 1 more");
    assert_eq!(list.held_count(), 2);
}

#[test]
fn a_shared_result_moved_by_a_drag_saves_every_row() {
    let mut list = list_of(&[
        held_row("a.pdf", &["merged.pdf"], None),
        held_row("b.pdf", &["merged.pdf"], None),
    ]);
    list.select_all();
    assert_eq!(list.drag_files(|_| false), [PathBuf::from("merged.pdf")]);
    list.dragged_out(&[PathBuf::from("merged.pdf")]);
    assert!(list.entries().iter().all(|e| e.line().0 == DROPPED));
}

#[test]
fn a_drag_carries_held_results_of_the_selection() {
    // Rows: held a, running b, held c (its file is being saved), held d.
    // Selection a, b, c: only a.jpg goes; d isn't selected.
    // Also: an empty selection carries nothing.
    // (Build with held_row and a Running entry; skip = |p| p == "c.jpg".)
    assert_eq!(list.drag_files(|p| p == Path::new("c.jpg")), [PathBuf::from("a.jpg")]);
}

#[test]
fn a_press_inside_the_selection_waits_for_release() {
    // Rows 0..3 with 0 and 2 selected.
    assert!(list.press(2));
    assert_eq!(list.selection(), [0, 2]);
    assert_eq!(list.focus(), Some(2));
    // Release without a drag: the win layer calls click(2).
    list.click(2);
    assert_eq!(list.selection(), [2]);
    // A press outside the selection, or with one row selected, is a click.
    assert!(!list.press(1));
    assert_eq!(list.selection(), [1]);
}

#[test]
fn files_gone_after_a_drag_were_moved_not_lost() {
    let mut list = list_of(&[
        held_row("a.png", &["a.jpg"], None),
        held_row("b.png", &["b.jpg"], None),
    ]);
    let dragged: HashSet<PathBuf> = [PathBuf::from("a.jpg")].into();
    // b.jpg is missing too, but it wasn't dragged: that one is gone.
    assert!(list.settle_drags(&dragged, |_| false));
    assert_eq!(list.entries()[0].line().0, DROPPED);
    assert!(list.entries()[1].is_gone(|_| false));
    // Nothing more to settle.
    assert!(!list.settle_drags(&dragged, |_| false));
}

#[test]
fn a_drag_starts_past_the_system_distance() {
    assert!(!past_drag(2.0, -2.0, 2.0, 2.0));
    assert!(past_drag(2.5, 0.0, 2.0, 2.0));
    assert!(past_drag(0.0, -3.0, 2.0, 2.0));
}
```

`list_of` and `select_all` stand for whatever builds a `FileList` from entries and selects every row in the existing tests. Use the existing helpers and add one only if none exists. Fill in the two sketched tests with the row set their comments describe.

### Task 2: The drag

**Files:**
- Create: `crates/kiln-app/src/win/drag_out.rs`
- Modify: `crates/kiln-app/src/win/mod.rs` (`mod drag_out;`, App fields, `mouse_down`, `mouse_move`, `mouse_up`, `check_gone`, WM_KILN_DRAG/DROP handling, `DropTarget::new` call at the RegisterDragDrop site)
- Modify: `crates/kiln-app/src/win/drop.rs` (own-drag flag)
- Modify: `crates/kiln-app/src/win/system.rs` only if a public way to count the drag as a modal is needed (reuse `window_loop(true/false)`)

**Interfaces:**
- Consumes: everything Task 1 produces.
- Produces:
  - `drag_out::drag_files(hwnd: HWND, files: &[PathBuf]) -> windows::core::Result<()>`. It builds the shell data object, sets the preferred effect, turns async off and runs the drag.
  - `DropTarget::new(hwnd: HWND, own: Rc<Cell<bool>>)`. While `own` is true, DragEnter, DragOver and Drop return `DROPEFFECT_NONE` and send nothing.

- [ ] **Step 1: Write `drag_out::drag_files`.** Exact calls, in order:
  1. For each file, `SHParseDisplayName` to an absolute PIDL.
  2. `SHCreateShellItemArrayFromIDLists` over them.
  3. `IShellItemArray::BindToHandler::<IDataObject>(None, &BHID_DataObject)`.
  4. Set `CFSTR_PREFERREDDROPEFFECT` (`RegisterClipboardFormatW`) with an HGLOBAL holding `DROPEFFECT_MOVE` as a u32, using `SetData(.., fRelease = true)`.
  5. `cast::<IDataObjectAsyncCapability>()` and `SetAsyncMode(false)`. If the cast fails, go on: the object is then synchronous.
  6. `SHDoDragDrop(hwnd, &data, None, DROPEFFECT_MOVE | DROPEFFECT_COPY)`.
  7. Free every PIDL with `CoTaskMemFree`, on every path.

  Ignore the returned effect: the caller checks the files. `DRAGDROP_S_CANCEL` and `DRAGDROP_S_DROP` both count as `Ok`.

- [ ] **Step 2: Wire the drop target.** Add `own_drag: Rc<Cell<bool>>` to `App`, shared with `DropTarget::new`. Also make WM_KILN_DRAG and WM_KILN_DROP do nothing while it's set (a second guard).

- [ ] **Step 3: Wire the pointer.**

  App gets `list_press: Option<ListPress>` (`row: usize`, press point in DIPs, `collapse: bool`) and `dragged: HashSet<PathBuf>`.

  **In `mouse_down`, list branch, plain press on row `i`:**
  - If it isn't a cancel or link hit, call `files.press(i)` instead of `click(i)`.
  - If the row is held, not saving, its results exist, and Kiln has a holding folder, set `list_press` and `SetCapture`.

  **In `mouse_move`:** with `list_press` set, the left button down (`MK_LBUTTON` from the message), and `model::past_drag` true:
  - The halves are `GetSystemMetrics(SM_CXDRAG) / 2` and `SM_CYDRAG / 2`, converted to DIPs with the window's scale.
  - Take `list_press`, `ReleaseCapture`, and collect `files.drag_files(skip)`. `skip` is saving files or `!p.exists()`.
  - If any files are left:
    - Set `own_drag` and count a modal with `system::window_loop(true)`.
    - Call `drag_out::drag_files`.
    - Undo both, even on error.
  - Then:
    - `moved` = carried files that no longer exist.
    - Insert every carried file into `dragged`.
    - Call `files.dragged_out(&moved)` if any moved.
    - On `Err`, `say(model::DRAG_FAILED)`.
    - Invalidate.

  **In `mouse_up`:** take `list_press`. If it was set with `collapse`, call `files.click(row)`.

  **In `check_gone`:** first call `files.settle_drags(&self.dragged, |p| p.exists())`, and invalidate if it changed anything. Then the existing gone check.
