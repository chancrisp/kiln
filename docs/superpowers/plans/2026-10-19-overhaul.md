## Review Focus

1. **Two Kiln windows open at once.** Each holds and exports its own results. Neither sweeps the other's run folder.
2. **Export across drives.** A failed or partial copy leaves the held file intact and the row still exportable.
3. **Close with jobs running and results held.** One prompt covers both. Cancel really cancels the close (WM_CLOSE returns without DestroyWindow).
4. **Multi-select plus the wheel.** Right-clicking an unselected row resets the selection to that row. Merge appears only when the selection allows it.
5. **High contrast on.** Nothing is drawn in theme colours that vanish against system colours, and focus stays visible.

### Task 1: Holding and export in kiln-core

**Files:**
- Create `crates/kiln-core/src/held.rs`.
- Modify `crates/kiln-core/src/lib.rs` (exports).
- Reuse `output::create_unique` and the move logic in `job.rs::place`.

**Interfaces (Produces):**
- `pub struct Holding { dir: PathBuf, _lock: File }`
- `Holding::open(root: &Path) -> Result<Holding>` creates `root\<pid>-<unix millis>` and its `lock` file. The lock is held open with share mode 0, so other processes can't delete it.
- `Holding::dir(&self) -> &Path`
- `Holding::discard(self) -> Result<()>` removes its own folder.
- `pub fn sweep_stale(root: &Path) -> Vec<PathBuf>` removes each direct child folder of `root` whose `lock` can be deleted, and returns what it removed. It never follows links and never touches anything that isn't a direct child folder containing a `lock` file.
- `pub fn export_into(held: &Path, dir: &Path) -> Result<PathBuf>` moves `held` into `dir` under a unique name (`name (1).ext` rule).
- `pub fn export_as(held: &Path, dest: &Path) -> Result<PathBuf>` moves `held` to exactly `dest`, replacing it. Use this only after a Save dialog confirmed the name.
- Both export functions rename on the same volume. Across volumes they copy to a temp name in the destination, flush, rename into place, then remove the held file. On any error, the held file stays and a partial temp copy is removed.

- [ ] Write tests:
  - Two `open`s give different dirs.
  - `sweep_stale` keeps a locked dir, removes an unlocked one, ignores files and dirs without `lock`, and touches nothing outside root.
  - `export_into` names collide to `a (1).jpg`.
  - `export_as` replaces.
  - Cross-volume: an `#[cfg(test)]` hook forces the copy path, the copy works, and a simulated copy failure leaves the source in place.
- [ ] Run `cargo test -p kiln-core --lib held` and expect failures.
- [ ] Implement.

### Task 3: Held results in the window

**Files:**

**Window behaviour:**
- **Launch:** `sweep_stale(%LOCALAPPDATA%\Kiln\held)`, then `Holding::open`. Every job's `Options.out_dir` is the holding dir.
- **Export (one row):** the Save dialog (`IFileSaveDialog`, overwrite prompt on) for one output, or a folder picker for several.

  - Ctrl+S exports the selected row, and Ctrl+Shift+S exports all.

- **Shutdown:** `ShutdownBlockReasonCreate` / `Destroy` follows `held_count() > 0`.
- **On a normal exit:** `Holding::discard`.
- **Errors:** an export failure goes on the row line in brick. Export all reports `Saved 4 of 5. 1 couldn't be saved.`
- **Docs:** update README (lines ~27, ~103, ~212, and a CLI note) and DESIGN.md › Progress and results, per the spec.

### Task 11: UI Automation provider (spec §6, UIA)

**Files:** create `crates/kiln-app/src/win/uia.rs` and modify `win/mod.rs`. Enable the `windows` crate features for `Win32_UI_Accessibility` if missing.

- **The tree:** `WM_GETOBJECT` with `UiaRootObjectId` returns a root `IRawElementProviderSimple` + `IRawElementProviderFragmentRoot`. Each child is a fragment built from a snapshot of the app's state (a pure `fn a11y_tree(&App) -> Node`), with `Node { role, name, rect, children, states }`.
- **Patterns:**
  - Invoke (buttons, menu items)
  - SelectionItem (rows)
  - Selection (list)
  - Value or RangeValue (steppers)
  - SelectionItem for segments and tabs
- **Events:** `UiaRaiseAutomationEvent` for focus changes, and `UiaRaiseNotificationEvent` for status changes. On close, call `UiaReturnRawElementProvider(hwnd, 0, 0, null)` and `UiaDisconnectProvider` for each provider.
- **Threading:** the providers hold a weak handle to the snapshot and must answer from any thread. Use an `Arc<Mutex<Node>>` swapped on each repaint.
