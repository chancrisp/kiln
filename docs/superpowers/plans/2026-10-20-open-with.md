# Open with and Send to Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The MSI adds Kiln to Explorer's Open with, for every file type
Kiln converts from, and adds a Kiln shortcut to the installing account's
Send to. Kiln never becomes a default app.

**Architecture:**
- A checked-in WiX fragment lists the file types, and a kiln-core test
  keeps it equal to the format registry.
- `kiln.wxs` adds:
  - the `Applications\kiln-app.exe` entry
  - a `Kiln.Convert` ProgID
  - a per-user Send to shortcut component
- Kiln already handles files passed as arguments, including handing them
  to an open window. Its only change is a version resource, so Open with
  shows "Kiln".

**Tech Stack:** Rust (kiln-core tests), WiX Toolset 5
(`C:\Users\chanm\.dotnet\tools\wix`), embed-resource (`kiln.rc`),
PowerShell (`packaging/package.ps1`).

**Spec:** `docs/superpowers/specs/2026-10-20-open-with-design.md`

## Global Constraints

- **Branch:** `open-with`.
- **Git:**
  - Never push, and never merge without the owner's yes.
  - Commits use the owner's git identity, with no AI attribution or
    trailers.
- **Never install or uninstall the MSI.** That's the owner's check.
  Building and decompiling it is fine.
- **Copy, verbatim:**
  - Open with name: `Kiln`
  - ProgID: `Kiln.Convert`
  - Send to shortcut name: `Kiln`
  - Open command: `"[INSTALLFOLDER]kiln-app.exe" "%1"`
  - Version resource: FileDescription `Kiln`, ProductName `Kiln`
- **Never written:**
  - an extension's default value
  - `UserChoice`
  - `MultiSelectModel`
  - any custom action
- **Extensions:** lowercase, with a dot in the registry. They are the
  extensions Kiln converts from: each format with at least one target,
  plus its aliases.
- **Gates:**
  - `cargo fmt --all -- --check`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo test -p kiln-core`
  - `cargo test -p kiln-app`

## Review Focus

1. **Open with on many files at once.** Explorer starts one Kiln per file
   at the same moment, and every file must land in one window with none
   lost. Covered by the Task 2 controller smoke: five simultaneous
   launches give five rows in one window.
2. **Paths with spaces, non-ASCII letters or commas.** The `"%1"` quoting
   must keep them whole. Covered by the Task 2 smoke: one file is named
   `two words ü, ok.png`.
3. **Never the default.** Nothing may write an extension's default value.
   Covered by the Task 2 decompile check: the only keys under
   `Software\Classes\.<ext>` are `OpenWithProgids` values.
4. **Uninstall leaves nothing.** Every registry value and the shortcut
   must sit in an MSI component, with no custom actions. Covered by the
   Task 2 decompile check: no `CustomAction`, and every Kiln key in a
   component.
5. **A format added later.** It must not silently miss Open with.
   Covered by the Task 1 drift test, which names the missing extension.

### Task 1: The file type list and its drift test

**Files:**
- Modify: `crates/kiln-core/src/registry.rs` (a new method and its test)
- Create: `packaging/open-with-types.wxs`
- Create: `crates/kiln-core/tests/packaging.rs`

**Interfaces:**
- Produces:
  - `Registry::input_extensions(&self) -> Vec<String>`: every extension
    of a format with at least one target, plus that format's aliases.
    Lowercase, no dot, sorted, without duplicates.
  - `packaging/open-with-types.wxs`: a WiX 5 fragment with
    `<ComponentGroup Id="OpenWithTypes" Directory="INSTALLFOLDER">`
    holding one `<Component>`. For each extension `<ext>` it has two
    values, each on its own line:
    - `<RegistryValue Root="HKLM" Key="Software\Classes\Applications\kiln-app.exe\SupportedTypes" Name=".<ext>" Type="string" Value="" />`
    - `<RegistryValue Root="HKLM" Key="Software\Classes\.<ext>\OpenWithProgids" Name="Kiln.Convert" Type="string" Value="" />`

    The first value carries `KeyPath="yes"`. Windows reads only the value
    names, so the empty data is fine. If WiX 5 rejects `Value=""`, see
    Task 2 Step 4.

- [ ] **Step 1: Write the failing tests**

In `registry.rs` tests:

```rust
#[test]
fn input_extensions_are_what_kiln_converts_from() {
    let r = Registry::builtin();
    let exts = r.input_extensions();
    for e in ["png", "jpg", "jpeg", "tif", "tiff", "mp4", "docx"] {
        assert!(exts.iter().any(|x| x == e), "{e}");
    }
    assert!(exts.windows(2).all(|w| w[0] < w[1]), "sorted, no duplicates");
    for e in &exts {
        let f = r.format(e).unwrap();
        assert!(!r.targets(f).is_empty(), "{e} has no target");
    }
}
```

In `crates/kiln-core/tests/packaging.rs`:

```rust
#[test]
fn the_open_with_list_matches_the_registry() {
    // Reads ../../packaging/open-with-types.wxs from CARGO_MANIFEST_DIR.
    // Collects the extensions from the SupportedTypes Names and from the
    // ".<ext>\OpenWithProgids" Keys separately.
    // Asserts each set equals input_extensions(). On failure, the message
    // lists "missing from the MSI: …" and "not a Kiln input: …".
}
```

Parse it with plain string splitting. The crate has no regex dependency;
don't add one.

- [ ] **Step 2: Run them and check they fail**

Run: `cargo test -p kiln-core input_extensions` and
`cargo test -p kiln-core --test packaging`

Expected:
- `input_extensions` fails to compile.
- The packaging test fails because the file can't be read.

- [ ] **Step 3: Implement `input_extensions`, and write the fragment**

Write the fragment from `input_extensions()`. A throwaway

commit a generator.

Start the fragment with a comment saying the test keeps it in step with

here.

- [ ] **Step 4: Run the tests and gates.** All pass.

### Task 2: The MSI entries, the version resource and the docs

**Files:**
- Modify: `packaging/kiln.wxs`
- Modify: `packaging/package.ps1` (the `wix build` line)
- Modify: `crates/kiln-app/assets/kiln.rc` and `crates/kiln-app/build.rs`
  (the version resource)
- Modify: `README.md` (Install), `CHANGELOG.md`

**Interfaces:**
- Consumes: `ComponentGroup Id="OpenWithTypes"` from Task 1.

- [ ] **Step 1: Add the version resource.**
  - Add a `VERSIONINFO` block to `kiln.rc` with:
    - `FileDescription` and `ProductName` set to `Kiln`
    - `OriginalFilename` set to `kiln-app.exe`
    - `FILEVERSION`/`PRODUCTVERSION` from the crate version
  - Pass the version numbers from `build.rs` as macros through
    `embed_resource::compile`'s macro argument
    (`CARGO_PKG_VERSION_MAJOR`, `_MINOR`, `_PATCH`), in place of `NONE`.
  - Check: after `cargo build --release -p kiln-app`, this prints `Kiln`:
    `(Get-Item target\release\kiln-app.exe).VersionInfo.FileDescription`

- [ ] **Step 2: Add the Open with component to `kiln.wxs`.** It is one
  component in `KilnFiles` with HKLM values under `Software\Classes`:
  - `Applications\kiln-app.exe`: `FriendlyAppName` = `Kiln`
  - `Applications\kiln-app.exe\shell\open\command` (default value) = the
    open command
  - `Kiln.Convert` (default value) = `Kiln`
  - `Kiln.Convert\DefaultIcon` (default) = `"[INSTALLFOLDER]kiln-app.exe",0`
  - `Kiln.Convert\shell\open\command` (default) = the open command

  Reference `OpenWithTypes` from the `Main` feature.

- [ ] **Step 3: Add the Send to component.**
  - Put it under `<StandardDirectory Id="SendToFolder">`.
  - It holds a non-advertised `Shortcut` named `Kiln`:
    - `Target="[INSTALLFOLDER]kiln-app.exe"`
    - `Icon="KilnIcon"`
  - Its key path is an HKCU value: `Software\Kiln`, `SendTo` = `1`,
    integer. That's how Windows Installer wants a per-user item in a
    per-machine package (ICE38/ICE43/ICE57).
  - Reference it from `Main`.

- [ ] **Step 4: Build the MSI.**
  - In `package.ps1`, add `packaging\open-with-types.wxs` to `wix build`.
  - Run: `.\packaging\package.ps1`
  - Expected: `dist\Kiln-<version>-x64.msi` is written, with no ICE errors.
  - If WiX rejects the empty `Value=""` from Task 1, use `Value="Kiln"` on
    both value lines and update the drift test's parser to match.
  - Don't install the MSI.

- [ ] **Step 5: Decompile and check (Review Focus 3 and 4).**
  - Run: `wix msi decompile dist\Kiln-<version>-x64.msi -o <scratch>\kiln-decompiled.wxs`
  - Then check that:
    - the file has no `CustomAction`
    - every `Software\Classes\.<ext>` key carries only the `Kiln.Convert`
      value under `OpenWithProgids`
    - the open command reads `"[INSTALLFOLDER]kiln-app.exe" "%1"`
    - the Send to shortcut and its HKCU key path are in one component
  - Write the findings into the task report.

- [ ] **Step 6: Write the docs.**
  - **README, Install:** add to the Installer bullet: "It also adds Kiln
    to Open with for the files it converts, and to Send to."
  - **CHANGELOG:** under the next version, add "The installer adds Kiln
    to Explorer's Open with and Send to."

- [ ] **Step 7: Run the gates.** All pass.
